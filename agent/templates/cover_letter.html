cybergod.ai — what it is, and the engineering behind it

Security sales dies on one sentence: "thanks, but we're covered." You cannot argue with it, because the customer holds the data and you hold a deck that looks like your competitor's. cybergod.ai removes that: it shows a company what it has already published to the internet, prices the consequence in euros, and names who would come for it — from public sources only, without touching a single system.

  • Autonomous reconnaissance. A company name resolves into the full internet-facing estate: ASN and BGP data (RIPE, CAIDA, PeeringDB), certificate-transparency logs, live TLS subject and SAN harvesting, DNS enumeration, corporate group-structure discovery for subsidiaries trading under other names, and 30+ Shodan super-filters including a live internal-CA issuer pivot. The operator never types an IP, an ASN or a network.
  • Zero-false-positive discipline. Every scope-widening step must prove ownership, not merely match a string: fail-closed ownership gates, co-tenant guards, per-pivot budgets with whole-pivot rollback, and a hard rule that an automated filter may flag but never gut a deliverable. Regression tests replay real incidents so a fixed failure cannot return.
  • Multi-vendor LLM orchestration. An evidence-selected model chain across different vendors (a rate limit or outage is provider-wide, so a backup must be a different company), deadline-aware budget allocation per call, strict JSON contract validation, tolerant parsing of every shape models really emit, and automatic failover. Quality is measured on the delivered artifact, never on the HTTP status code.
  • Guards against the worst failure mode. A hallucination guard cross-checks every CVE the model cites against the actual scan evidence and strips what it cannot verify; an independent auditor model from a different vendor reviews the findings before delivery. A fabricated fact in a customer deck is unrecoverable, so the architecture assumes the model will sometimes be wrong.
  • Quantification and compliance. FAIR-based risk in euros (ALE, PML, LEF, TEF, loss-exceedance curves), MITRE ATT&CK adversary modelling for DORA and TIBER-EU, and a NIS2 / CRA / EU AI Act grading module with a remediation roadmap.
  • Production, not a prototype. Python/FastAPI, React + Vite PWA, Node and pptxgenjs deterministic deck rendering, Docker Compose, Caddy auto-TLS, GitHub Actions to GHCR CI/CD, Grafana/Loki/Promtail observability, Trivy + CodeQL + gitleaks + ruff + pytest gates, self-patching infrastructure, zero-trust auth with emailed one-time codes, full EN/DE internationalisation, GDPR-compliant EU-only hosting, and a one-command pipeline that tests, deploys, verifies the running container by hash and tags a rollback point.
  • Economics that make it a business. A full assessment costs about $0.006 in inference, tracked to the cent in a persistent ledger and surfaced on a dashboard. The unit economics were designed in, not discovered later.

What I carry from that work into any role is not a stack list. It is a method: automate everything, make failure observable, never let a model decide a side effect, and verify the artifact rather than the intention.
