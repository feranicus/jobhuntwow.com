## 2026-09-21 — the wallet got a wall, and the operator got eyes

**The ask, verbatim:** *"my main moto you can't protect something that you can't see. We already had
an incident on jobhuntwow we can't afford another one... I need to see as well every user who is
trying to enter www.jobhw.org or www.jobhuntwow.com and all the defences and observability like we
have for www.cybergod.ai."*

Read first: the LLM-jacking report, `SECURITY_OBSERVABILITY_STACK.md` and
`VISITORS_BOTS_AND_TELEGRAM_ALERTS.md`. Then an audit of what was actually WIRED here, not merely
present. What follows is what the audit found and what was done about it.

### 1. The one open item from the incident that mattered most

The report's *still open* list, item 3: **"jobhuntwow still has no budget cap and no rate limit.
Authentication is now required, but self-signup is open. The same spend is available to anyone
willing to create an account, and nothing currently prevents it."**

That was exactly true. `llm_events.py` says of itself "NOT A BUDGET"; there was no other file.
`backend/app/llm_meter.py` is now asked **before** every paid call at all four chokepoints, with
four rules (global USD/day, per-account USD/day, per-account calls/hour, service calls/hour),
failing **open on a storage fault** and **closed on the budget**, sharing ONE pricing home with the
ledger, and charging `JHW_UNKNOWN_CALL_USD` for a call whose tokens cannot be known — because the
actor used the STREAMING endpoint, and a gate that only counts what it can price is a gate with a
door in it. `tests/test_security_console.py` asserts by AST that `gate()` runs before the request in
each of the four functions, and the mutation (deleting one gate) fails the suite.

`spend_watch.py` adds the second source: DigitalOcean's month-to-date usage, polled hourly, median
baseline with today excluded from its own baseline, a ratio AND an absolute floor, and any model
called today that was never called before is itself a finding. A meter-only watcher would have
reported a normal fortnight while the invoice tripled — which is what happened.

### 2. Two controls that were blind while reporting health

**The route-table gate saw 10 routes of 31.** FastAPI 0.139 stopped flattening `include_router()`
into `app.routes`: an included router is now one lazy `_IncludedRouter` object. The regression test
that was supposed to catch "a new route without a session dependency" was walking `app.routes` and
filtering for `APIRoute`, so it silently skipped every auth, electronic, tracker and `/v1` route —
including the `/api/electronic/*` tree that served another user's CV during the incident — and
reported a clean run. It is the same defect class as everything else in this file: a check that
cannot see its subject reporting a clean result. `authz_audit.iter_api_routes()` now descends, both
callers assert a floor of 25 routes, and the fix is proven by adding a public `/api/leak` route and
watching both the suite (exit 1) and the audit (exit 1) catch it.

**Two writers of `evt=http`.** The sidecar and observability both appended an access line; the only
thing stopping the double count was `PERSEUS_OBSERVE_HTTP=0` in one compose file, so any other way
of running the image doubled every number again. The nomination is now made in code, and only if
the nominated writer is importable.

Also fixed: `observability.emit`'s file write swallowed its exception (the one live writer in the
estate that did), and the HTTP alert rules had two homes with the live one being the copy nobody
maintained.

### 3. Seeing the short domain, which is what he actually asked for

`jobhw.org` was redirected by a `redir` line in the shared Caddyfile. One line, works, and the
request never reaches the only process that writes an event: **nobody who typed the short domain
appeared anywhere in our record**. Caddy now proxies it here and `backend/app/hosts.py` issues the
301 itself, after the request has been observed with `host=jobhw.org`. The destination is a constant
in that file, so it cannot become an open redirect; a hostname we do not own is served rather than
bounced; `/.well-known/` is never redirected, because a bounced ACME challenge is a certificate
outage for every domain on that host. `tests/test_gate_integrity.py`'s old check — "every `redir`
in the Caddy block points at the canonical host" — encoded the previous doctrine and was REWRITTEN
rather than deleted, with the old reasoning kept beside it, and the new one is proven by removing a
hostname from the app's claim and watching it fail.

### 4. The console

`GET /api/security/overview` + `/security`, administrator-only, checked server-side on every
request. Per-hostname traffic, three buckets, attack classes by shape, offenders ranked by DISTINCT
paths (a real visitor misses the same few stale pages; a scanner misses hundreds), what the shield
did, alerts fired AND suppressed, spend by account and by model, and a live feed of the last 200
requests. Every unreadable source renders `None` with a reason — never 0 — and every state word has
an `unknown`.

One measurement bug was caught by its own self-test while building it: `_probe_class` called
`perseus_client.probe_shape(path, False)`, but that parameter is a route PREDICATE, not a bool. The
TypeError was swallowed by a `try/except` and every path came back unclassified, so the console
would have reported **zero attacks** on a page whose entire purpose is to show them. READ THE
SIGNATURE, and prove the classifier answers before believing its zero.

### 5. Said out loud, not papered over

The WebRTC half of the browser probe is now **off at both ends** and needs `JHW_PROBE_WEBRTC=1` plus
`VITE_JHW_PROBE_WEBRTC=1`. The sibling estate evaluated the same technique and declined it: it
cannot see a scripted client (no JavaScript runs in one), it accuses corporate networks that block
UDP, and it unmasks an address the user chose to hide. It stays as evidence, never a gate.

Still open and not closable from this repo: the DigitalOcean model access key is shared, legacy and
unscoped across five projects. The allowlist closes one path and the budget closes another; a scoped
per-project key closes every path including the ones nobody has imagined, and it is console work.

### 2026-09-21, later — "I still can't see a stupid message that I visited the page"

He sent a screenshot of cybergod.ai's Telegram message — *A person just opened cybergod.ai*, with
When / Page / IP / Client / Referrer / Language — and asked why jobhuntwow never sends one.

It never sent one because it never existed. This project's feeds were `observe_login_success` and
`observe_new_job`: **both require an account**. An anonymous visit — the only signal that says
whether the site has any traffic at all — produced nothing anywhere. Not a bug in delivery, an
absent feature, and worth saying plainly rather than debugging Telegram.

`visitors.note_visit()` is the port, with four things the sibling paid for:

* **Gate on the PATH, not the user agent.** cybergod alerted "a person just opened cybergod.ai" for
  a scanner that asked for `/.svn/wc.db` while announcing itself as Safari on iOS. The UA is
  attacker-controlled; the path is the evidence. Ours refuses `/wp-login.php` by shape, using
  `perseus_client.probe_shape` — the one home — and a contract proves it.
* **Absence of evidence is still a person.** A record that contradicts itself is a client; a record
  carrying nothing to look at is unjudged and **still reported**, because a corporate network strips
  exactly the headers that would prove a browser, and making that visitor invisible is the expensive
  error. Wrongly messaging about a bot is merely annoying.
* **It is a FEED, not an alert.** Own dedupe (one visitor per 6 h, keyed on address plus a coarse
  client fingerprint so a phone and a laptop on one office NAT are two people) and its own hourly
  cap, so it can never eat the storm cap that a real security alert needs.
* **Off the request path.** `notify.both` is a blocking HTTPS call; this runs while somebody is
  waiting for a page. `notify.fire_and_forget` sends on a daemon thread — measured: the page
  answered in 61 ms with a sender deliberately sleeping 2 s, and the message still arrived.

Two things this turn found that reading the code would not have:

1. The end-to-end proof had to drive the **real `serve.py`** out of `Dockerfile.web`, because
   `backend/app/main.py` alone has no SPA catch-all: every page route 404s in a bare harness, and
   the feed correctly stays silent on a 404. A test against `app.main` would have "proved" the
   feature was broken.
2. The first version's `from . import perseus_client` inside a `try/except: pass` meant the
   path-shape rule **silently never ran** when the module is executed as a script, which is exactly
   how ship.py runs it. Caught by the contract failing, not by review. Presence is not reachability,
   and a swallowed import is how a control becomes decorative.

The console now shows reported visits, held-back visits, and the reasons, so the next "why did I get
no message" is a page to look at rather than a guess.

## 2026-09-22 — the project portfolio, and "Top 5 reasons why you should hire me"

Two asks, both from the Tailor page:

> *"add option to add project portfolio and take items from it to include in Cover letter or in
> resume specifically important for position description"*
> *"make cover letter in TOP 5 format ... this needs to be an optional bullet point if a stakeholder
> wants to make a top 5 cover letter he needs to choose this option"*

### The portfolio is a store, and the selection is arithmetic

`/evidence/upload` already took a document per run, which means re-attaching the same case studies
for every application — against the product promise. A project is a fact about the candidate, not
about one job, so `backend/app/portfolio.py` keeps it per account and every later run reads it.

**Which projects matter for a posting is decided by counting, not by a model.** The posting's own
words are matched against each project's stack, tags, title and role (weighted: a named stack entry
is a deliberate claim, a word in a summary is prose). That is instant, free, explainable, and
structurally incapable of naming a project that does not exist — the same closed-set rule the panel
obeys everywhere else in this codebase. Each selection carries the posting terms that produced it,
so a derived fact stays labelled, and `POST /portfolio/preview` shows the choice **before** any
model is called or any document is written. `portfolio_ids` lets him override the arithmetic
entirely: his judgement beats the counting, always.

**A posting that matches nothing selects nothing.** Padding a cover letter with irrelevant work is
the behaviour the feature replaces, so the honest empty is the answer and the manifest says which it
was (`portfolio_note`).

### TOP-5 is a contract, not a prompt

Asking a model for "top 5 reasons" and rendering whatever comes back is how you ship a top-5 letter
with four reasons. `contract_ok_cover(..., fmt="top5")` requires **exactly five**, each carrying at
least 40 characters of proof; anything else is a rejected draft that walks the model chain like any
other quality failure. `revision_ok` applies the same contract to the audit round, so a later
reviewer may make the five truer and may not turn them back into four paragraphs of prose — the
format is his choice, not the auditor's.

`documents.py` renders them as five **numbered** points in the DOCX and the PDF, because the entire
point of the format is that the reader can count them.

### Two things the suite caught that reading the code would not

1. **A floor must be measured against the document it guards.** `MIN_COVER=700` was derived from
   250-350 words of prose. A legitimate five-reason letter measures ~580, so the first version
   rejected every good top-5 draft as THIN and walked the whole chain failing. `MIN_COVER_TOP5=500`
   comes from the format's own arithmetic, and `cover_depth` now counts `reasons` rather than only
   `paragraphs` — a check pointed at a field the document does not use is a check that cannot pass.
2. **Two checks that could not fail.** The endpoint test's fixture profile was 48 characters, which
   cleared the "too thin to tailor from" floor **only** because the portfolio block was appended to
   it. The run with the portfolio switched off therefore 400'd, and the two assertions that read the
   captured prompt both passed on an empty capture — "the portfolio did not reach the writer" is
   trivially true when nothing reached the writer. The suite now asserts the call SUCCEEDED before
   reading anything it captured.

Also fixed on the way: two projects created in the same millisecond got the same id (the second
overwrote the first wherever the id is the key), and `GenerateReq.email` was a required body field
that the handler overwrites from the session on its first line — demanding it only made a correct
request fail with a 422.

### 2026-09-22, later — "I have my project portfolio as PDF"

Typing a portfolio that already exists as a document is exactly the manual data entry this product
promises not to ask for, so `POST /api/electronic/portfolio/upload` takes PDF, DOCX, TXT or MD
through the same extraction path the profile uses, and `portfolio.parse_text` splits it.

The split is deterministic and its rules come from how people actually lay these files out: a short
line that is not a sentence starts a project; `Stack:` / `Technologies:` / `Role:` / `Client:` lines
go to their own fields; `-`, `*`, `•` and `1.` lines become achievements; a date range in the title
line becomes the period and is removed from the title; a URL in the block is kept. **Every value it
proposes is a substring of the uploaded file** — asserted by the suite, which flattens the source
text and checks every field of every proposed item against it.

**It proposes; it does not save.** Parsing somebody's layout is guesswork by nature — two columns, a
table, a designed CV — so the items come back for review, land in the editor, and only his Save
writes them. Mutating the endpoint to save directly fails the suite (`2 -> 4` stored). That is the
same rule the rest of the codebase obeys: deterministic code may propose, the human decides the
side effect.

Two parser defects the suite caught immediately, both of which would have looked like "the import is
broken" in his hands:

1. **A section header swallowed the first project.** `MY PROJECT PORTFOLIO` was a heading with no
   body, so the real first heading beneath it was appended as its *body* and the section label was
   proposed as a project. Two headings in a row now mean the first was a label: replace it.
2. **A wall of prose with no headings produced one untitled row holding the whole document.** A
   block with no title is now only a project if it carries structure of its own (bullets, a stack,
   a link); otherwise the answer is the honest "no project could be split out of these N
   characters", with advice to put each project under its own short title.

Verified end to end through the real endpoint with a real `python-docx` file and a real `reportlab`
PDF, not with fixtures: both return the same two projects, with the stack that then makes them
selectable for a posting. An image-only PDF returns `only 0 characters of text could be read from
this file` rather than an empty proposal.

### 2026-09-22 — the run log: "we literally do not have any direct logging per each time we use the platform"

He sent the cybergod.ai console beside a JobHuntWOW cover letter: one of them shows every step of the
run as it happens and hands you a `_Run_Log_EN.txt` afterwards, the other shows a percentage. He is
right, and the gap was real — the Tailor page had a progress bar whose text was written in advance,
which is the opposite of a record.

`backend/app/runlog.py` is the store: a bounded, per-run, per-owner buffer, plus a `.txt` written
into the job folder and listed with the documents. Three decisions worth keeping:

* **Polling, not SSE.** A run is 15-45 seconds, the endpoint sits behind a proxy that buffers, and a
  poll with an `after` index cannot half-work. A stream that silently stalls looks exactly like a
  run that hung.
* **A line is written when something HAPPENS.** `RC.tailor(on_event=...)` now reports the chain, the
  author, every draft verdict **with the depth measured and the reason it was refused**, the auditor
  and its vendor, and every revision applied or refused. `[draft] cover deepseek-3.2 REJECTED
  depth=472 <- THIN: floor is 500` is worth more than any number of "35% writing your documents".
* **It is his.** The log carries the employer, the role, the model chain and what the run cost, so
  `read()` checks the owner: another account gets `known: false`, anonymous gets 401, and an unknown
  or expired run is not an error — the page polls before the POST is handled and long after the
  buffer expires.

instructive:

1. **A file the page LISTS must be one the server SERVES.** The run log appeared beside the DOCX and
   the PDF and then returned HTTP 400 on download, because `docnames.looks_generated()` — the one
   home for "is this one of ours" — had never heard of a `.txt`. A file offered and refused is worse
   than one never offered.
2. **The suite's own HTTP harness did not split the query string**, so `/runlog/x?after=0` matched
   the route with a run_id of `x?after=0` — an unknown run — and the poller got 200 with an empty
   list. Six checks then reported "the log does not stream" about a log that streamed perfectly.
   A harness defect that reads as a product defect is the expensive kind, and the fix is written
   down beside the code that broke.
